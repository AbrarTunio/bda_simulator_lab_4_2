Explained simply

Nine ideas, each one used in a step.

1Spark in one sentence

Spark splits data into partitions and runs the same work on each partition at the same time, keeping data in memory between steps where it can. That is why it is much faster than MapReduce, which writes to disk between every map and reduce.

Same map and reduce ideas as lab 4.1, much less code, much less disk.

2RDD: the low-level API

An RDD is a distributed list of items. You process it with your own Python functions: map, filter, reduceByKey. Spark cannot look inside those functions, so it runs them exactly as written, in the order written.

Powerful and flexible, but you are the optimiser.

3DataFrame: the high-level API

A DataFrame is a table with named columns. You say what you want (groupBy("host").agg(sum("bytes"))), and Spark's optimiser, Catalyst, decides how: which columns to read, where to filter, when to combine.

Shorter code and faster runs, for the same reason.

4Lazy: nothing runs until you ask

read›filter›groupBy›show()

Transformations (map, filter, groupBy, join) only add to a plan and return instantly. Actions (count, show, collect, take, write) run the whole plan.

So timing a transformation measures nothing, and a mistake only shows up at the action.

5Narrow and wide

Narrow: map, filter
each partition works alone
Wide: groupBy, join
data moves between partitions

Every wide step is a shuffle, and every shuffle splits the job into another stage. Fewer shuffles, faster job.

6reduceByKey vs groupByKey

groupByKey sends every single value across the network, then adds them. reduceByKey adds them up inside each partition first, then sends one number per key.

It is the combiner from lab 4.1, built in. Same answer, a tiny fraction of the shuffle.

7Reading a plan

explain() prints how Spark will run a DataFrame query. Read the physical plan from the bottom up. Every Exchange line is a shuffle.

Count the Exchanges, and you know how many shuffles you are paying for.

8Skewed joins, and two fixes

A join sends all rows with the same key to the same task. If one host has 60% of the rows, one task does 60% of the work. Broadcast: copy the small table to every worker, so nothing moves. Salting: split the busy key into several sub-keys.

Broadcast when one side is small; salt when both sides are big.

9Cache, coalesce, write

cache() keeps a result in memory for reuse, but only after an action fills it, and only worth it if you reuse it. coalesce(n) reduces the number of output files without a shuffle.

Measure before and after; never cache by habit.

Words you will meet

Partition
One slice of the data. One task processes one partition.
Shuffle / Exchange
Moving rows between partitions so equal keys meet. The expensive part.
Stage
A group of tasks that run without a shuffle. A shuffle ends a stage.
Catalyst
Spark's query optimiser for DataFrames and SQL.
Broadcast join
Send the small table to every worker, so the big one never moves.

The web page on port 4040 showing jobs, stages, tasks and storage.
